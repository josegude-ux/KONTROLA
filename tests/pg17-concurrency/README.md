# VISURA F3A R4.1 — ensayo PG17 de dos sesiones (NO EJECUTADO)

Este material es una **propuesta de prueba para un entorno PostgreSQL 17 efímero, aislado y autorizado**. No es un workflow ni crea servicios. Nunca conectarlo a Supabase, KONTROLA operativo, BC o producción. El runner de KONTROLA consultado utiliza PostgreSQL 16; no modificarlo ni lanzarlo sin autorización.

La instalación de ensayo exige que previamente se haya creado y verificado una base nueva, vacía, llamada exactamente `visura_f3a_qa_r41_20261117`, en un servicio PostgreSQL 17 desechable. Este paquete **no crea esa base ni el servicio**. El SQL `00_fixture.sql` crea roles `anon` y `authenticated` exclusivamente en esa instancia efímera, funciones ficticias `auth.*` y dos cargas sintéticas; por eso no debe ejecutarse en un clúster que contenga otras bases de datos relevantes. El archivo R4.1 incluido procede del blob original `68db4e388a99ff8631d0de279879a707807d2b59`, sin transformaciones.

El lanzador `scripts/ensayo-f3a-r41-dos-psql-pg17.sh` exige una autorización futura explícita mediante `VISURA_F3A_ALLOW_LOCAL_QA=EXPLICIT_ISOLATED_POSTGRES17` y comprueba nombre de base, IP de servidor local, usuario y versión PostgreSQL. Estas comprobaciones **no prueban por sí solas** que `127.0.0.1` no sea un túnel: se requiere inspección externa del servicio, runner y aislamiento por el responsable antes de activarlo. No proporciona ni guarda secretos. No ejecutarlo con conexión redirigida, ni con credenciales remotas.

El lanzador inicia dos procesos `psql` con sesiones distintas, espera la marca `A_WRITTEN` emitida después de ejecutar un check pero antes del COMMIT, abre B y observa `pg_stat_activity` buscando `wait_event_type=Lock` para el PID de B. Rechaza PASS sin PIDs distintos, espera real, SQLSTATE 40001 en CAS, un solo evento para UUID repetido, contadores consistentes y RPC sin EXECUTE para `anon`/`authenticated`. Durante la espera A conserva bloqueos durante 7 segundos; límites y logs se guardan solo en el área local de pruebas. **No se ejecuta ninguna suite histórica.**

Esta prueba homologaría la concurrencia del contrato SQL en un PostgreSQL 17 sintético. **No homologaría** Supabase Auth real, seguridad RLS del entorno remoto, IndexedDB/iPhone ni publicación. Tras el ensayo el servicio/instancia completa debe destruirse conforme a autorización; no usar scripts destructivos contra bases existentes.
